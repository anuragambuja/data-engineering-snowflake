# Snowflake

- Sanoflake is a cloud-native data platform offered as a service.
  - Cloud Native
    - Snowflake’s software is purpose built for the Cloud.
    - All Snowflake infrastructure runs on the Cloud in either AWS, GCP or Azure.
    - Snowflake makes use of Cloud’s elasticity, scalability, high availability, cost-efficiency & durability.

  - Data Platform
     
      ![image](https://github.com/user-attachments/assets/5883647a-4a60-439a-a278-33a171222260)

  - Software as a service
    - No Management of hardware
    - Transparent updates and patches
    - Subscription payment model
    - Ease of access
    - Automatic Optimization

- It was originally designed to run on AWS and then ported to Azure in 2018, and then to Google Cloud Platform in 2020.
- All data files are automatically encrypted by default, using aes256 strong encryption.

> ## Multi-cluster Shared Data Architecture

  ![image](https://github.com/user-attachments/assets/9cc555c9-156d-4dfa-a70c-31dacaa27a37)

- Storage Layer
  - Persistent and infinitely scalable cloud storage residing in cloud providers blob storage service, such as AWS S3.
  - Snowflake users by proxy get the availability & durability guarantees of the cloud providers blob storage.
  - Data loaded into Snowflake is organized by databases, schemas and accessible primarily as tables. When data files are loaded or rows inserted into a table, Snowflake reorganizes the data into its proprietary compressed, columnar table file format. The data that is loaded or inserted is also partitioned into what Snowflake call micro-partitions. 
  - Both structured and semi-structured data files can be loaded and stored in Snowflake.
  - Storage is billed by how much is stored based on a flat rate per TB calculated monthly.
  - Data is not directly accessible in the underlying blob storage, only via SQL commands.

- Query Processing Layer
  - The query processing layer consists of “Virtual Warehouses” which is a Snowflake object you create via SQL commands. A Virtual Warehouse is a named abstraction for a cluster of a cloud-based compute instances that Snowflake manage.

    ```
    #  Below statement will create the virtual warehouse which will be composed of EC2 instances (if used in AWS) arranged together as a distributed compute cluster. These run the software of the execution engine Snowflake designed for the cloud. This carries out the computation task of the query plan generated by the services layer.  We have no direct access to those nodes. We interact with just the abstracted warehouse object.
    CREATE WAREHOUSE MY_WH WAREHOUSE_SIZE=LARGE;
    ```
  - Virtual warehouses make a remote call to the storage layer when a query is issued to them, and then the raw table data retrieved is stored on a local cache made up of high-speed storage. This cache data can be used to compute results for subsequent queries.
  - Behind the scenes, Snowflake will provision the compute instances when a create statement is issued and remove them when it's dropped. Once they've been created, virtual warehouses can be paused or resumed.In the pause state, you're not charged for compute.
  - Virtually unlimited number of virtual warehouses can be created each with it’s own configuration.
  - Virtual warehouses come in multiple “t-shirt” sizes indicating their relative compute power. They range from extra small to six times extra large.
  - Snowflake is not an eventually consistent system, it uses strict ACID-compliant processing to ensure that all updates and inserts are immediately available to all virtual warehouses. This is primarily achieved by a service in the global services layer called the transaction manager, which synchronizes data access.
